# V0.8 Phase 1 - Agent Registry / Child Agent Identity

## 1. Scope

V0.8 Phase 1 adds the minimum Kernel identity layer needed before process
trees, delegation, IPC, or resource sharing can be introduced.

Implemented scope:

- Kernel-owned `AgentRegistry`.
- Root Agent and child Agent registration.
- Parent / child Agent identity relation.
- Deterministic Agent Tree queries.
- Deny-by-default child principal creation.
- Durable `agent/created` semantic fact.
- Registry reconstruction from Session event logs.
- Fail-closed handling for conflicting durable identity facts.

This phase does not implement multi-Agent execution. It only makes Agent
principals explicit, queryable, and recoverable.

This implementation follows:

- `docs/architecture/V0.8_MULTI_AGENT_ARCHITECTURE_REVIEW.md`
- `docs/architecture/V0.8_MULTI_AGENT_DESIGN_FREEZE.md`

The preserved boundary is:

- Agent = capability principal and semantic actor.
- Process = schedulable runtime identity.
- Session = durable single-writer journal and replay truth.
- Agent Tree is not Process Tree.

## 3. AgentRegistry

`AgentRegistry` lives in `agentkernel.agent` and is exported from
`agentkernel`.

The public API is:

- `create_root(...)`
- `create_child(...)`
- `register_root(...)`
- `register_child(...)`
- `record_agent_created(...)`
- `get(agent_id)`
- `contains(agent_id)`
- `parent_of(agent_id)`
- `children_of(agent_id)`
- `root_of(agent_id)`
- `lineage(agent_id)`
- `reconstruct(sessions)`
- `from_sessions(sessions)`

The registry owns in-memory identity indexes only. It does not execute Agents,
create Processes, admit work to the scheduler, grant capabilities, or exchange
messages.

## 4. Identity Rules

Each Agent has a stable `agent_id`. Each Agent also has a primary `session_id`.

Rules:

- `agent_id` must be unique inside the local Kernel runtime identity domain.
- `session_id` must not be shared by multiple registered Agents.
- A root Agent has `parent_agent_id = None`.
- A child Agent has a non-empty `parent_agent_id`.
- A child parent must already exist in the registry.
- An Agent cannot be its own parent.
- Cycles are rejected during reconstruction.

Duplicate Agent ids are rejected with `AgentAlreadyExists`. Missing or invalid
parents are rejected with `InvalidAgentParent`. Corrupted replay facts are
rejected with `AgentRegistryCorruptionError`.

## 5. Parent / Child Model

The parent / child relation is represented directly on
`AgentControlBlock.parent_agent_id`.

`AgentRegistry` keeps a deterministic child index. `children_of(agent_id)`
returns direct child Agent ids in creation order. `lineage(agent_id)` returns
ancestry ordered from root to the requested Agent.

Multiple root Agents are supported. The registry is forest-compatible rather
than built around one global root.

## 6. Deny-by-Default Child

`create_child(...)` creates a new capability principal with no copied authority.

Child defaults:

- `capabilities = frozenset()`
- `capability_bounding_set = frozenset()`
- `capability_grants = ()`

Parent capability copy: **NO**.

This applies to legacy capability strings and structured `CapabilityGrant`
values. Delegated or narrowed child grants are deferred to a later V0.8 phase.

## 7. Durable Creation Facts

Agent identity creation is persisted as a semantic Session event:

```json
{
  "type": "agent/created",
  "data": {
    "agent_id": "agent-child",
    "parent_agent_id": "agent-root",
    "session_id": "session-child",
    "creation_id": "create-child"
  }
}
```

Root Agent facts use `"parent_agent_id": null`.

The fact intentionally stores identity metadata only. It does not serialize a
live `AgentRegistry`, `AgentControlBlock`, Process state, scheduler state,
budget usage, delegated grants, IPC state, or resource ownership.

## 8. Reconstruction

`AgentRegistry.reconstruct(sessions)` scans loaded Session events for
`agent/created` facts and rebuilds a fresh in-memory registry.

Replay semantics:

- Replaying the same creation fact more than once is idempotent.
- Replaying a different creation fact for the same `agent_id` is corruption.
- Replaying a reused `creation_id` with different identity data is corruption.
- A child fact whose parent is absent is corruption.
- A cycle in durable parent relations is corruption.

Reconstruction restores identity graph state only. It does not restore live
Process runtime state or capability delegation state.

## 9. Error / Corruption Rules

Phase 1 fails closed for security-relevant identity ambiguity:

- Duplicate live Agent id: `AgentAlreadyExists`.
- Unknown parent during live child registration: `InvalidAgentParent`.
- Shared primary Session id: `AgentTreeError`.
- Invalid durable creation payload: `AgentRegistryCorruptionError`.
- Conflicting durable identity fact: `AgentRegistryCorruptionError`.
- Missing parent or cycle during reconstruction:
  `AgentRegistryCorruptionError`.

The implementation does not use last-write-wins repair for Agent lineage.

## 10. Backward Compatibility

Existing `Agent.create(...)` behavior remains compatible:

- `parent_agent_id` is optional and defaults to `None`.
- Existing single-Agent construction does not emit `agent/created`.
- Existing V0.7 Sessions without `agent/created` events still load.
- Capability evaluation continues to use `agent_id` as the subject.
- Process ids remain runtime identities and never become authorization subjects.

## 12. Limitations

Phase 1 does not implement:

- Process Tree.
- Full `spawn_agent()`.
- Process scheduling for child Agents.
- Capability Delegation.
- `DelegatedGrant`.
- IPC, mailbox, queue, or channel.
- Resource sharing.
- Ownership transfer.
- Budget hierarchy.
- Fault propagation.
- Cancellation propagation.
- Namespace, Memory, RBAC, IAM, or revocation.
- Multi-Agent execution.
- Multi-Agent RuntimeBench.

## 13. Deferred to Phase 2+

Later phases must define:

- Process Tree and supervision metadata.
- Scheduler admission for child Processes.
- Capability delegation and narrowing.
- Kernel IPC channels and durable message envelopes.
- Resource sharing grants.
- Budget, cancellation, and fault isolation.
- Multi-Agent recovery semantics.
- Multi-Agent RuntimeBench evidence.
