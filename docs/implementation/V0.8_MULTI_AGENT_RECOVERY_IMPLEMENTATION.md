# V0.8 Multi-Agent Recovery Implementation

V0.8 Phase 7 adds a thin integrated recovery coordinator for the multi-agent
runtime surface. The coordinator rebuilds Kernel-owned runtime indexes from
durable facts and reports recovery obligations without mutating the recovered
logs or resuming execution.

## Implemented Scope

- Reconstructs `AgentRegistry` from `agent/created` and delegated capability
  facts.
- Reconstructs `ProcessManager` from `process/created` facts.
- Optionally reconstructs `ResourceShareRegistry` when a `ResourceStore` is
  supplied.
- Optionally reconstructs `KernelIPC` from an `IPCPersistence` boundary.
- Preserves `Session.recovery_analysis` output for each supplied Session.
- Reports durable side-effect obligations that still require Host policy action.
- Returns a fresh `CooperativeScheduler` without admitting recovered processes.

## Recovery Semantics

Integrated recovery is intentionally read-only. It does not append Session
events, append IPC records, retry tools, reconcile durable operations, enqueue
processes, or restart any Agent loop. Durable facts remain the source of truth;
the returned runtime objects are fresh indexes over those facts.

Process dispositions are mechanism-level signals:

- `NOT_ADMITTED`: the Process identity was reconstructed, but it has not been
  admitted to a new live scheduler.
- `NEEDS_RECONCILIATION`: at least one durable side effect in the owning Session
  requires Host reconciliation or manual action before further side effects.
- `CORRUPTED`: reserved for callers that need to persist a per-process
  corruption disposition; current corruption is raised as an exception.

## Not Implemented

- No automatic reconcile, retry, restart, or scheduler admission.
- No two-phase commit across Sessions or IPC.
- No namespace, RBAC, IAM, revocation, or policy engine.
- No V0.9 memory integration.

## Validation

`tests/test_v0_8_multi_agent_recovery.py` covers integrated replay across Agent,
Process, Resource sharing, IPC, and durable side-effect recovery obligations. It
also verifies that corrupted cross-boundary facts are rejected through
`MultiAgentRecoveryCorruptionError`.
