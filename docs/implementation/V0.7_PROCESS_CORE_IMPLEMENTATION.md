# V0.7 Process Core Implementation

Status: Phase 1 implementation.

Scope:

- Add the minimal Process runtime primitives required before a Scheduler.
- Keep `AgentControlBlock`, `Session`, and `DefaultAgentLoop` compatible.
- Do not implement Scheduler queues, IPC, delegation, namespace, RBAC, or multi-agent runtime.

## 1. Implemented Objects

### ProcessState

`ProcessState` defines the Kernel-owned lifecycle vocabulary for future schedulable execution:

```text
CREATED
READY
RUNNING
WAITING
BLOCKED
PAUSED
EXITED
```

This intentionally differs from legacy `AgentState`:

- `CREATED` replaces the process meaning previously approximated by `AgentState.NEW`.
- `BLOCKED` is new and represents Kernel conditions that prevent progress.
- `FAILED` is not a process state. Failure is represented as `EXITED` plus `exit_status`.

### CapabilitySnapshot

`CapabilitySnapshot` captures an immutable view of Agent-owned authority for process accounting:

- `agent_id`
- legacy capability strings
- legacy bounding set
- structured `CapabilityGrant` values

The snapshot does not make Process the authorization subject. V0.6 authorization still uses Agent identity.

### ProcessControlBlock

`ProcessControlBlock` is the minimal Kernel-owned Process record. It contains:

| Field | Purpose |
|---|---|
| `process_id` | Runtime identity for a schedulable process instance. |
| `agent_id` | Agent principal that owns capability authority. |
| `session_id` | Durable journal backing this process. |
| `state` | Current `ProcessState`. |
| `parent_process_id` | Future process tree/cancellation propagation hook. |
| `priority` | Scheduler input, not policy by itself. |
| `budget` | Existing `AgentBudget` compatibility bridge for Phase 1. |
| `wait_reason` | Required only in `WAITING`. |
| `blocked_reason` | Required only in `BLOCKED`. |
| `cancel_requested` | Sticky cancellation signal for future scheduler safe points. |
| `pause_requested` | Sticky pause signal for future scheduler safe points. |
| `capability_snapshot` | Required Agent-derived capability snapshot. |
| `exit_status` | Required only in `EXITED`. |

## 2. Lifecycle Validation

The Process Core validates explicit state transitions:

| From | Allowed next states |
|---|---|
| `CREATED` | `READY`, `EXITED` |
| `READY` | `RUNNING`, `PAUSED`, `EXITED` |
| `RUNNING` | `READY`, `WAITING`, `BLOCKED`, `PAUSED`, `EXITED` |
| `WAITING` | `READY`, `PAUSED`, `EXITED` |
| `BLOCKED` | `READY`, `PAUSED`, `EXITED` |
| `PAUSED` | `READY`, `EXITED` |
| `EXITED` | none |

State-specific metadata is also validated:

- `WAITING` requires `wait_reason`.
- `BLOCKED` requires `blocked_reason`.
- `EXITED` requires `exit_status`.
- These fields are rejected on unrelated states.

## 3. Recovery Mapping

`ProcessControlBlock.from_recovery()` converts replay facts into a live Process state:

| Recovery fact | Process state |
|---|---|
| Completed session | `EXITED`, `exit_status="completed"` |
| Corrupted session | `EXITED`, `exit_status="corrupted"` |
| Active context compaction | `BLOCKED`, `blocked_reason="context_compaction_recovery"` |
| Durable operation requires reconcile/manual handling | `BLOCKED`, `blocked_reason="durable_operation_recovery"` |
| Ordinary interrupted prefix | `READY` |

This preserves the V0.2/V0.3 rule that durable facts are replayed, not guessed. A dispatched durable side effect without commit remains a recovery condition, not a fresh execution opportunity.

## 4. Compatibility

V0.7 Phase 1 does not alter existing runtime boundaries:

- `AgentControlBlock` remains the Agent identity and capability principal.
- `Session` remains the append-only durable event log.
- `DefaultAgentLoop` remains the single-agent turn driver.
- Tool, Resource, Durable Tool, Context VM, and Recovery boundaries remain unchanged.
- `AgentBudget` is reused as the Phase 1 process budget compatibility bridge.

The new Process Core can wrap existing Agent/Session pairs without changing how callers run a turn today.

## 5. Not Implemented

This phase intentionally does not implement:

- Scheduler run queues.
- Wait queues or block registries.
- Time-slice dispatch.
- IPC.
- Delegation.
- Revocation.
- Namespace isolation.
- Multi-agent execution.
- Policy engine or scheduling policy.

## 6. Test Coverage

Added `tests/test_process_core.py` covering:

- process creation from `AgentControlBlock`;
- valid lifecycle transitions;
- invalid transition rejection;
- recovery mapping into process state;
- dispatched durable operation recovery blocking;
- Agent-owned capability preservation.

## 7. Next Phase

The next V0.7 phase can add a cooperative Scheduler over these primitives:

- process table;
- ready queue;
- wait/block registries;
- safe-point dispatch around the existing loop;
- pause/resume and cancellation checks.

That next phase should still keep scheduling mechanism separate from host policy.
