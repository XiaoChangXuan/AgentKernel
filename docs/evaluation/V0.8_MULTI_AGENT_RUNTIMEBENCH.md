# V0.8 Multi-Agent RuntimeBench

Status: implemented as deterministic offline RuntimeBench evidence.

Decision:

```text
V0.8_MULTI_AGENT_RUNTIMEBENCH_COMPLETE
```

## Scope

V0.8 Phase 8 extends RuntimeBench from the V0.7 single-agent runtime families
to multi-agent runtime invariants. It does not add new Kernel features and does
not implement Phase 9 Memory, Namespace, RBAC, IAM, distributed runtime, or
revocation.

The benchmark artifact is:

```text
benchmarks/results/runtimebench_v0.8.json
```

The unified runner is:

```text
python -m benchmarks.runtimebench
```

## Benchmark Family

RuntimeBench V0.8 includes B1 through B8:

| Family | Mechanism evidence |
| --- | --- |
| B1 Fault Tolerance | Session replay, recovery analysis, durable operation classification, process recovery mapping. |
| B2 Side Effect Safety | Durable Tool WAL, operation identity, reconcile after crash. |
| B3 Context Efficiency + Truth Preservation | Context VM, Resource Handle, exact large payload preservation. |
| B4 Capability Isolation | Tool, Resource, and Durable Tool authorization boundaries. |
| B5 Resource Governance | UsageCollector, scheduler safe-point blocking, budget recovery. |
| B6 Long-Horizon Runtime Stability | Single-agent 100/500/1000 step composition of V0.1-V0.7 mechanisms. |
| B7 Boundary Isolation | Agent, Process, Session, Context, Accounting, and ResourceStore boundary invariants. |
| B8 Multi-Agent Runtime | Multi-agent identity, delegation, IPC, resource sharing, budget isolation, fault isolation, recovery, and long-horizon composition. |

## B8 Cases

| Case | Oracle |
| --- | --- |
| M1 Agent / Process identity isolation | Agent is the capability principal; Process is only runtime identity. |
| M2 Agent tree / Process tree separation | Agent lineage and process supervision remain separate indexes. |
| M3 Capability delegation narrowing | Child capability cannot widen parent action, scope, or constraints. |
| M4 IPC delivery / authority isolation | IPC payload delivery does not install capability authority. |
| M5 Resource sharing isolation | Shared resource access requires both share and capability. |
| M6 Hierarchical budget isolation | Process, Agent, and Host budget scopes block independently. |
| M7 Fault / cancellation isolation | Child fault or cancellation does not erase supervisor state. |
| M8 Integrated multi-agent recovery | Recovery reconstructs agents, processes, IPC, resource shares, and durable WAL obligations. |
| M9 Authority shrink after restart | Current parent authority bounds replayed delegation after restart. |
| M10 Long-horizon multi-agent composition | Multi-agent invariants hold for 100, 500, and 1000 logical steps. |

## Required Invariants

B8 passes only if all M1-M10 cases pass and these counters remain zero:

- `unauthorized_effects`
- `unsafe_duplicate_effects`
- `cross_agent_resource_leaks`
- `authority_escalations`
- `lost_durable_facts`
- `recovery_corruptions`
- `unresolved_mandatory_wal`

M10 additionally requires:

- logical steps equal requested steps;
- IPC send, delivery, and ack counts match;
- horizon 100, 500, and 1000 profiles all pass.

## Evidence Claims Allowed

V0.8 RuntimeBench supports these scoped claims:

- implemented V0.8 multi-agent primitives preserve tested identity,
  authority, resource sharing, IPC, budget, fault, and recovery invariants in
  deterministic offline fixtures;
- multi-agent recovery can reconstruct tested AgentRegistry, ProcessManager,
  IPC, ResourceShareRegistry, and WAL obligation state without deleting durable
  facts;
- IPC payloads are delivery facts, not capability grants;
- delegated child authority remains bounded by current parent authority during
  replay.

## Claims Not Allowed

The benchmark does not justify claims about:

- production sandbox security;
- distributed runtime correctness;
- complete revocation semantics;
- namespace security;
- RBAC, IAM, or user systems;
- persistent memory correctness;
- model intelligence or semantic task quality;
- superiority over another agent framework or product.

## Limitations

- The fixture is synthetic and local.
- The benchmark is deterministic and offline.
- It measures runtime invariants, not model reasoning ability.
- Timing is local-machine observational data.
- B8 uses AgentKernel public runtime APIs but does not compare against external
  multi-agent frameworks in this phase.
