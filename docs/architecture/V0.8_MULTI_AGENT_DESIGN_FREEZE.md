# V0.8 Multi-Agent Runtime Design Freeze

Status: implementation contract derived from
`V0.8_MULTI_AGENT_ARCHITECTURE_REVIEW.md`.

Decision:

```text
READY_FOR_V0.8_IMPLEMENTATION
```

This document freezes the V0.8 design contract. It intentionally avoids
implementation code and does not claim V0.8 is implemented.

## 1. Frozen Object Model

```text
Agent   = capability principal and semantic actor
Process = schedulable runtime identity
Session = durable single-writer journal and replay truth
IPC     = Kernel-owned communication mechanism between Agents/Processes
```

V0.8 must not collapse these objects into one transcript or one loop object.

## 2. Frozen Identity Rules

| Rule | Frozen decision |
| --- | --- |
| Agent principal | Capability subject remains Agent-owned. |
| Process identity | Process is runtime state and scheduling target. |
| Child process | Does not create a new capability principal. |
| Child Agent | Creates a new capability principal. |
| Process authority | Cannot inherit or expand authority by process lineage. |
| Capability snapshot | Remains attribution/sanity metadata, not an authority source. |

## 3. Frozen Tree Model

V0.8 has two related trees:

```text
Agent Tree: semantic and authority lineage
Process Tree: runtime scheduling and supervision lineage
```

The two trees may reference each other but must not be merged.

## 4. Frozen Session Ownership

Default:

```text
one Agent -> one primary Session
```

Rules:

- Session remains single-writer.
- Multiple Agents do not co-write one Session.
- Cross-Agent cooperation uses Kernel IPC.
- Parent does not automatically read child Session.
- Cross-session correlation uses `message_id`, `correlation_id`, spawn id, or
  future audit identity.
- A future global audit index must not replace per-Session replay truth.

## 5. Frozen Spawn Semantics

`spawn_process()`:

- creates another schedulable runtime instance for the same Agent;
- does not create a new capability principal;
- does not widen authority;
- must respect Session single-writer constraints.

`spawn_agent()`:

- creates a new Agent principal;
- creates or binds a child Session;
- creates at least one Process for execution;
- validates delegated authority before the child can act;
- admits the child Process through Scheduler mechanism.

Frozen flow:

```text
Parent Process
  -> spawn request
  -> Kernel shape validation
  -> Host policy decision
  -> child Agent identity
  -> delegated grant narrowing validation
  -> child Session
  -> child Process
  -> Scheduler admission
```

`spawn request` is never itself an authority grant.

## 6. Frozen IPC Model

Primitive:

```text
Kernel-owned local structured channel
```

Required message envelope fields:

- `message_id`;
- `channel_id`;
- `sender_agent_id`;
- `sender_process_id`;
- `receiver_agent_id`;
- optional `receiver_process_id`;
- JSON-compatible `payload`;
- optional `resource_refs`;
- `sequence`;
- `correlation_id`;
- timestamp or monotonic ordering metadata.

Invariant:

```text
Data may cross IPC.
Authority does not cross IPC implicitly.
```

IPC payloads may contain requests, handles, and facts. They must not silently
grant tool, resource, durable mutation, memory, or delegation authority.

## 7. Frozen IPC Durability

V0.8 first version should use:

```text
local durable message envelope with explicit delivery state
```

Guarantee:

```text
at-least-once observable delivery until ack, with receiver de-duplication by
message_id
```

Do not claim exactly-once delivery.

Required crash semantics:

| Crash point | Frozen recovery rule |
| --- | --- |
| Send recorded, receiver has not received | Envelope remains pending. |
| Delivered, receive event not durable | Redelivery allowed. |
| Receive event durable, ack missing | Receiver de-duplicates by message id; ack repair allowed. |
| Ack durable | Envelope is complete. |

## 8. Frozen IPC Ordering

Minimum ordering:

```text
per-channel FIFO for one sender on one channel
```

No global total order is promised. Multi-sender order must be explicit in
channel sequence metadata if a future policy requires it.

## 9. Frozen IPC Backpressure

Kernel mechanism:

- count messages;
- count queued bytes;
- enforce hard bounds;
- BLOCK or reject sender according to configured channel mode;
- expose WAITING/BLOCKED reason.

Host policy:

- choose bounds;
- choose timeout;
- choose reject/drop/block behavior;
- choose retry and supervision behavior.

Default recommendation:

```text
bounded channel + sender BLOCKED when full
```

## 10. Frozen Delegation Invariant

```text
child effective authority <= delegated authority <= parent effective authority
```

Delegation must be:

- explicit;
- positive;
- structured;
- narrowed;
- provenance-carrying;
- compatible with future revocation.

Required delegation metadata:

- `delegation_id`;
- `parent_agent_id`;
- `child_agent_id`;
- parent grant reference or fingerprint;
- narrowed `action`;
- narrowed `resource_scope`;
- narrowed `constraints`;
- optional expiry or lease metadata;
- audit/correlation identity.

Do not copy parent grant strings into the child.

## 11. Frozen Inheritance Rule

Child Agent default authority:

```text
deny by default
```

Inherited by default:

- parent identity reference;
- supervision relation;
- optional policy references;
- maximum budget ceiling.

Not inherited by default:

- tool authority;
- resource authority;
- durable mutation authority;
- memory authority;
- namespace authority.

## 12. Frozen Resource Sharing

Rule:

```text
ResourceHandle reference != authority
```

If Agent A sends a handle or URI to Agent B, B cannot read it unless a separate
authorization path permits it.

V0.8 default:

```text
share grant, not ownership transfer
```

ResourceStore remains a byte driver. ResourceService remains the authorization
boundary.

## 13. Frozen Confused Deputy Rule

Receiver authority does not automatically permit leaking protected results back
to the sender.

V0.8 must carry caller provenance and must require either:

- delegated task authority;
- response-channel authorization;
- explicit resource share grant;
- host policy approval.

## 14. Frozen Budget Model

Hierarchy:

```text
Host global budget
  -> Agent budget
      -> Process budget
```

Kernel mechanism:

- observe usage;
- attribute to process and Agent;
- enforce hard ceilings at safe points;
- block/pause/cancel only through lifecycle rules.

Host policy:

- allocate budget;
- choose overage handling;
- choose model/provider cost model.

Accounting remains runtime observation, not durable billing truth.

## 15. Frozen Fault Isolation

Rule:

```text
child crash != parent crash
```

Kernel records child exit status and notifies or wakes the supervisor. Parent
policy decides ignore, retry, restart, fail-fast, or ask user.

Child failure must not corrupt parent Session truth.

## 16. Frozen Cancellation Model

Default:

```text
structured lifetime, parent cancellation propagates downward
```

Detached children are out of scope for the first implementation unless a later
review explicitly admits them.

Durable rule:

```text
cancel before dispatch can stop the effect;
cancel after dispatch requires WAL recovery/reconcile.
```

## 17. Frozen Context Isolation

Rules:

- ContextWorkingSet is process/session scoped.
- Context Page is projection, not durable authority.
- Agents do not share raw context.
- Cross-agent data moves through IPC or Resource sharing only.

## 18. Frozen Scheduler Compatibility

Scheduler continues to schedule Processes.

V0.8 extends Scheduler around:

- process hierarchy metadata;
- IPC WAITING/BLOCKED reasons;
- cancellation propagation;
- budget attribution;
- supervision notifications.

V0.8 must not replace Scheduler with an Agent scheduler.

## 19. Frozen Durable vs Runtime State

Durable:

- Agent identity;
- Agent parent relation;
- child creation fact;
- Session events;
- delegated grants and provenance;
- IPC message envelope and delivery state;
- Resource ownership and share grants;
- Durable Tool WAL.

Runtime:

- READY queue;
- current RUNNING process;
- WAITING/BLOCKED registries;
- process table indexes;
- usage counters;
- ContextWorkingSet.

Persist semantic facts. Reconstruct live runtime state.

## 20. Deferred Items

Not in V0.8:

- distributed agents;
- remote IPC;
- cluster scheduling;
- RBAC;
- IAM;
- general namespace framework;
- full revocation engine;
- persistent memory;
- network sandbox;
- preemptive scheduling;
- consensus;
- distributed transaction;
- workflow DSL.

## 21. Frozen Implementation Phase Order

Recommended order:

1. Agent Registry and child Agent identity.
2. Process Tree and supervision metadata.
3. Capability Delegation Core.
4. Kernel IPC channels.
5. Resource Sharing grants.
6. Budget, fault, and cancellation isolation.
7. Multi-agent recovery semantics.
8. Multi-Agent RuntimeBench.

Implementation may split these further, but it must not introduce IPC authority
transport or shared Session writing as a shortcut.

## 22. Final Decision

```text
READY_FOR_V0.8_IMPLEMENTATION
```

This freeze authorizes a future V0.8 implementation plan. It does not implement
V0.8 and does not modify runtime code.
