## 1. Evidence Scope

RuntimeBench V0.7 is an offline deterministic runtime-mechanism benchmark. It is
not an agent intelligence benchmark, not a production security audit, and not a
cloud performance benchmark.

The current evidence supports narrow claims about AgentKernel runtime
mechanisms:

- durable recovery behavior over the implemented crash prefixes;
- side-effect safety for the fake payment WAL scenario;
- context/resource pressure behavior for deterministic large artifacts and
  1000-turn context fixtures;
- capability denial at Tool, Resource, and Durable Tool boundaries;
- cooperative scheduler budget blocking at explicit safe points;
- kernel object boundary invariants for Agent, Process, Session, Context,
  Accounting, and ResourceStore responsibilities.

## 3. Claims Not Supported

The current RuntimeBench evidence does not support these claims:

- AgentKernel is more intelligent than another agent framework.
- AgentKernel outperforms Codex, Gemini, OpenHands, Letta, LangChain, or any
  other runtime.
- The WAL provides universal exactly-once semantics for arbitrary external
  systems.
- Capability enforcement is a complete production sandbox.
- Capability supports delegation, revocation, namespaces, RBAC, IAM, or
  multi-agent ownership.
- Scheduler enforcement is preemptive.
- RuntimeBench proves scalability across many processes.
- Context VM preserves arbitrary semantic facts, as opposed to the current
  marker-based fixture.
- B1 covers corrupted events, partial writes, or long replay scalability.
- B6 long-horizon composition is validated.
- V0.8 Process Tree, IPC, Multi-Agent, Namespace, Delegation, or Memory features
  are implemented or validated.

## 4. B5 Resource Governance Review

B5 verifies:

- token budget pressure;
- tool-call budget pressure;
- resource-byte budget pressure;
- wall-time budget pressure;
- scheduler safe point blocking;
- unblock recovery after host-controlled usage reset.

Generated B5 metrics:

| Metric | Value |

| `budget_case_count` | 4 |
| `blocked_case_count` | 4 |
| `blocked_correctness` | true |
| `resource_usage_accuracy` | true |
| `usage_snapshot_accuracy` | true |
| `safe_point_blocking_success` | true |
| `unblock_correctness` | true |
| `budget_recovery_success` | true |

Interpretation:

B5 supports the claim that the V0.7 scheduler can use `UsageCollector`
observations to block a process at cooperative safe points when runtime budgets
are exceeded. It also supports the intended boundary that accounting remains
observation: host policy can reset usage and unblock, while durable Session
truth is not rewritten by the accounting subsystem.

Limitations:

- No preemptive scheduling.
- No OS-level CPU or memory quota.
- No distributed resource accounting.
- No durable billing ledger semantics.

## 5. B7 Boundary Isolation Review

B7 verifies:

- Agent is the capability principal; Process is runtime identity.
- Process state changes do not mutate Session truth.
- Session events can change without mutating Process lifecycle state.
- Context pages are projections, not durable truth.
- Accounting observations do not themselves authorize or transition a process.
- ResourceStore is storage; ResourceService remains the authorization boundary.

Generated B7 metrics:

| Metric | Value |
| --- | --- |
| `boundary_invariant_passed` | true |
| `authority_leak_count` | 0 |
| `durable_truth_mutation_count` | 0 |
| `object_identity_confusion_count` | 0 |
| `regression_count` | 0 |

Interpretation:

B7 supports the V0.7 object-model claim that Agent, Process, Session, Context,
Accounting, and ResourceStore remain distinct kernel concepts. The benchmark is
especially important before V0.8 because Process Tree and IPC must build on
these boundaries rather than collapse them.

Limitations:

- Single-agent only.
- No child process ownership.
- No IPC channel boundary.
- No namespace normalization.
- ResourceStore authority is checked through denied `ResourceService.read`
  behavior, not by a formal static interface proof.

## 6. Benchmark Limitations

Global limitations:

- Synthetic fixtures.
- Offline execution.
- No real model provider calls.
- No network services.
- Local filesystem behavior only.
- Latency numbers vary by machine and should be treated as local observations.
- No statistical repeated-run analysis.
- No adversarial fuzzing.

Coverage gaps that should remain explicit:

- B6 Long-Horizon Runtime Stability is not implemented.
- B8 Scheduler Scalability is not implemented.
- Partial writes and corrupted event logs are not covered by RuntimeBench V0.7.
- Semantic retrieval and semantic summarization baselines are not covered.
- Production sandbox escape resistance is not covered.

## 7. Final Review

Decision:

```text
V0.7_RUNTIMEBENCH_EVIDENCE_COMPLETE_FOR_B1_B5_B7
```

The V0.7 evidence is sufficient to claim that the implemented kernel runtime
mechanisms work for the deterministic scenarios covered by B1 through B5 and
B7. It is not sufficient to claim V0.8 readiness for Process Tree, IPC,
Multi-Agent, Delegation, Namespace, or Memory implementation.
