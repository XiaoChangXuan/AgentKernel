# AgentKernel V0.9B Memory Correctness

Status: implemented as a minimal correctness layer on top of V0.9 Persistent
Memory.

V0.9B answers one narrow question:

```text
If remembered information becomes stale, conflicts with another memory, or is
superseded by newer evidence, how does Kernel preserve that uncertainty without
pretending it knows the truth?
```

## Core Claim

Memory is remembered knowledge, not objective truth.

Durable means the proposition and lifecycle facts were recorded. Durable does
not mean fresh, current, or authoritative.

```text
          Durable Memory
                |
        +-------+--------+
        |                |
      ACTIVE           STALE
        |                |
        |                +-- evidence provenance
        |
   conflict relation
    /            \
  M1              M2
    \            /
     \          /
      Context Projection
            |
            v
       model-visible
   "conflicting memories"
```

```text
Memory M1
"Python 3.11"
      |
      | newer evidence
      v
Current Observation
"Python >= 3.12"
      |
      v
explicit mark_stale
      |
      v
M1 remains durable
but is excluded from default retrieval
```

## Lifecycle

V0.9B projects four lifecycle states:

| State | Meaning |
| --- | --- |
| `ACTIVE` | Usable by default retrieval and normal Context projection. |
| `STALE` | Durable history remains, but the memory is no longer default-usable because explicit newer evidence made it questionable. |
| `SUPERSEDED` | A specific newer `MemoryRecord` explicitly replaces the older one. |
| `FORGOTTEN` | Semantically inactive for default retrieval; not secure physical deletion. |

`STALE` and `SUPERSEDED` are deliberately different. Stale means "do not use by
default without a freshness review." Superseded means "use this explicit newer
memory instead."

## Correctness Operations

V0.9B adds explicit lifecycle and relation mechanisms:

- `MemoryService.mark_stale(...)`
- `MemoryService.mark_conflict(...)`
- existing `MemoryService.supersede(...)` with lifecycle state projection
- existing `MemoryService.forget(...)` with lifecycle state projection
- `MemoryService.history(...)` for authorized lifecycle/audit inspection

All lifecycle mutations are append-only `MemoryEvent` facts. The store remains
durable event truth; active records, stale records, conflict metadata, and search
indexes are projections.

## Provenance

Freshness and conflict metadata must include provenance.

For example, a stale transition can say:

```text
reason: pyproject.toml now requires Python >=3.12
evidence_provenance:
  source: current-observation
  source_session_id: session-current
  source_event_id: tool-result-9
  source_tool_name: read_file
```

This tells a reader why the memory was marked stale without requiring Kernel to
decide whether the outside world is globally true.

## Conflict

Conflict is not corruption.

Two memories can both remain active while carrying a conflict relation:

```text
M1: Project requires Python 3.11
M2: Project requires Python 3.12
conflict_group: conflict_mem_0000_mem_0001
```

Kernel does not infer this from text. A host, policy layer, or future memory
policy must explicitly call `mark_conflict(...)`. V0.9B only records, restores,
filters, and projects the relation.

Scope matters. `mark_conflict(...)` rejects relations that cross owner/namespace
boundaries, because many apparent contradictions are simply scoped facts.

## Retrieval

Default retrieval returns only active memories:

```python
memory.search(..., include_stale=False, include_superseded=False, include_forgotten=False)
```

Audit/debug retrieval can inspect history:

```python
memory.history(...)
```

Callers can explicitly include inactive categories in search, but the default
remains conservative:

- stale memories are hidden
- superseded memories are hidden
- forgotten memories are hidden
- active conflicting memories are returned together with conflict metadata

## Context Projection

`project_memories_to_context_pages(...)` now includes model-visible metadata:

- `memory_id`
- `status`
- `namespace`
- `source`
- `provenance`
- stale metadata when explicitly projected
- supersede metadata when explicitly projected
- conflict relation metadata when present

Default projection filters to active memories even when callers pass a mixed
history list. Conflict diagnosis can use:

```python
project_conflicting_memories_to_context_pages(...)
```

This makes the model see the uncertainty as uncertainty:

```text
[Conflicting memory]
- content: Preferred implementation language is Python.
  memory_id: mem_0000
  status: ACTIVE
  conflict_group: conflict_language
  conflicts_with: mem_0001
  note: conflicting memories are preserved; Kernel does not choose truth
```

## Capability

Memory lifecycle mutation is authority-gated:

- read/search/history require `memory.read`
- remember/mark_stale/mark_conflict require `memory.write`
- supersede requires `memory.write` and `memory.forget`
- forget requires `memory.forget`

Knowing a `memory_id` or holding a projected context page is not permission.

## Recovery

`JsonlMemoryStore` remains append-only. A fresh Python runtime rebuilds:

- active/stale/superseded/forgotten lifecycle state
- supersede chain metadata
- conflict group and relation metadata
- stale evidence provenance

The lexical index is still rebuildable and not durable truth.

## Non-Goals

V0.9B does not implement:

- vector database
- embeddings
- RAG framework
- LLM contradiction judge
- truth verification
- poisoning policy
- shared-memory policy
- CRDT
- knowledge graph
- automatic world-model

Reactivation is also deferred. If stale memory later appears valid again, create
a new `MemoryRecord` with fresh provenance instead of mutating the old event
history back to active.

## Review Questions

1. Durable Memory 为什么不等于 Fresh Memory？

   Durable only means the remembered proposition and its lifecycle facts were
   recorded. Freshness requires newer evidence and explicit lifecycle state.

2. Stale 和 Superseded 有什么语义区别？

   Stale has evidence that makes the memory questionable without naming a
   replacement. Superseded names a specific newer memory that replaces the old
   one.

3. 两个冲突 Memory 为什么不能视为 store corruption？

   Conflict can be a valid historical or scoped state. Corruption means durable
   facts cannot be projected coherently; conflicting propositions can still be
   coherent facts about what was remembered.

4. Kernel 为什么不自动选择“更可信”的那一个？

   Trust ranking is policy. Kernel records provenance, relation, and lifecycle
   state, but does not run a truth policy or LLM judge.

5. Current observation 和 Memory 的 provenance 有什么区别？

   Current observation provenance points to a recent tool/session event.
   Memory provenance points to the remembered proposition's original source.

6. Stale Memory 为什么应该默认不进入 Context？

   It is known to be questionable for current use. It remains available through
   history/debug paths but should not silently steer the model.

7. Conflict Memory 为什么有时需要同时投影给模型？

   When diagnosis or resolution is the task, hiding one side would fabricate
   certainty. Projection should show both with relation metadata.

8. Supersede chain 如何防止 cycle？

   `MemoryService.supersede(...)` rejects duplicate memory ids before appending,
   and projection validates supersession facts against active state and chain
   consistency.

9. Lifecycle mutation 如何受到 Capability 约束？

   `mark_stale` and `mark_conflict` require `memory.write`; `supersede` requires
   both `memory.write` and `memory.forget`; `forget` requires `memory.forget`.

10. Restart 后 correctness metadata 是否完整恢复？

   Yes for the implemented JSONL/InMemory stores: lifecycle, stale provenance,
   supersede links, and conflict relations rebuild from durable events.

11. 有没有为了实现 freshness 而把 Policy 塞进 Kernel？

   No. Kernel never reads pyproject or chooses truth on its own. Callers provide
   explicit evidence provenance and lifecycle operations.

12. 当前实现距离真正的“truth verification”还缺什么？为什么那些不属于 V0.9B？

   It lacks external fact checking, trust scoring, embeddings, semantic NLI,
   poisoning defenses, and domain policy. Those decide truth or trust; V0.9B is
   only the mechanism for recording and projecting uncertainty.
