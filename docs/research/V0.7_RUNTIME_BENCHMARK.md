## Scope

This benchmark validates V0.7 runtime primitives only:

- `ProcessControlBlock` lifecycle transitions
- `CooperativeScheduler` READY, WAITING, and BLOCKED handling
- `UsageCollector` and scheduler budget blocking
- `ProcessUsageSnapshot`
- process-state reconstruction from Session recovery analysis
- Agent / Process / Session identity separation

It does not benchmark or implement V0.8, Process Tree, IPC, multi-agent
scheduling, delegation, namespace, Resource Layer changes, Durable WAL changes,
Capability architecture changes, or Context VM changes.

## Interpretation

The benchmark confirms the current V0.7 runtime primitives work as mechanisms:

- lifecycle transitions reject invalid ownership by staying inside the
  `ProcessControlBlock` state machine;
- scheduler registries track READY, WAITING, and BLOCKED live runtime state;
- budget enforcement is a cooperative safe-point behavior;
- usage accounting is observable runtime state, not a durable ledger;
- process crash recovery is reconstructed from Session replay facts;
- capability ownership remains Agent-owned and does not move to Process.

## Limitations

- The benchmark is synthetic and offline.
- It does not measure model intelligence or prompt quality.
- It does not measure production latency.
- It does not persist process tables or accounting counters.
- It does not cover V0.8 IPC, Process Tree, multi-agent ownership, delegation,
  revocation, or namespace.
