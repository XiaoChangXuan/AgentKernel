# AgentKernel V0.8.0-alpha Release Notes

## Overview

AgentKernel V0.8.0-alpha is a local, deterministic, alpha-stage multi-agent
runtime baseline.

It extends the V0.7 Process Runtime with Agent identity, Process Tree metadata,
Capability Delegation, Kernel IPC, explicit Resource Sharing, hierarchical
runtime isolation, integrated multi-agent recovery, and Multi-Agent
RuntimeBench evidence.

This release is not production-ready software and is not a production sandbox.
It is a release-candidate evidence freeze for tested runtime mechanisms.

## What V0.8 Adds

- Agent Registry and child Agent identity.
- Process Tree and supervision metadata.
- Capability Delegation with narrowing and durable provenance.
- Kernel IPC channels with durable envelopes and at-least-once delivery until
  ack.
- Explicit Resource Sharing grants for cross-Agent resource access.
- Hierarchical runtime budget, fault, and cancellation isolation.
- Integrated multi-agent recovery over Agent, Process, Session, IPC, Resource
  sharing, and Durable Tool WAL facts.
- Multi-Agent RuntimeBench B8 with M1-M10 deterministic offline cases.

## Architecture Boundaries

The V0.8 object model is:

```text
Agent   = capability principal and semantic actor
Process = schedulable runtime identity
Session = durable single-writer semantic journal
```

Key boundaries:

- Agent Tree and Process Tree are separate.
- Process lineage does not grant authority.
- IPC moves data, not authority.
- ResourceHandle is a reference, not permission.
- Cross-Agent Resource access needs current capability and an active
  ResourceShare.
- Capability snapshots are metadata, not authority sources.
- Runtime usage accounting is observation, not durable billing truth.
- Recovery reconstructs fresh runtime mechanisms from durable semantic facts.

## Upgrade / Compatibility Notes

- The Python package version is aligned to `0.8.0a0`, the PEP 440 equivalent of
  `0.8.0-alpha`.
- Existing V0.7-style Process creation remains compatible.
- Existing V0.5 Resource owner access remains compatible.
- Legacy `required_capability` strings remain compatible with structured
  `CapabilityGrant` evaluation.
- RuntimeBench V0.8 supersedes RuntimeBench V0.7 as current release evidence;
  V0.7 artifacts remain historical evidence.

## Limitations

V0.8.0-alpha does not provide:

- V0.9 Persistent Memory.
- Namespace security.
- Complete revocation semantics.
- RBAC or IAM.
- Production sandbox security.
- Distributed runtime correctness.
- Distributed consensus.
- Multi-user security.
- Preemptive scheduling.
- Universal exactly-once side effects.
- Arbitrary external system atomicity.
- General production reliability.
- Model intelligence or task-quality improvement evidence.

RuntimeBench is deterministic, offline, local, and synthetic. It evaluates
runtime invariants rather than model reasoning ability.

## Next Direction

Reference applications and future runtime evolution are outside V0.8. The next
architecture area may study persistent memory, but persistent memory is not
implemented in this release.
