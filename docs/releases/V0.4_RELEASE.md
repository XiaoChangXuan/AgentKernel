# AgentKernel V0.4 Context VM

## Problem

模型上下文窗口有限，而 Agent 的持久状态和完整历史可以远大于当前模型窗口。V0.4 将完整事实历史与单次模型请求中可见的物理上下文分开。

## Design

Session Event Log 是 append-only 的持久事实源。Context Page、裁剪视图和 Summary 都是模型可见的派生表示；淘汰、裁剪与压缩均不删除或改写原始事件。

## Phase 1

- 当前工作集（Working Set）按预算选择 Context Page。
- 固定（Pin）保护必要上下文；超出预算时明确失败。
- 淘汰（Eviction）不等于删除；Page-In 支持按需重新换入。
- Tool Call 与 Tool Result 作为原子组选择。

## Phase 2

- 上下文压力驱动淘汰、确定性 Tool Result 裁剪和语义压缩。
- `head + omission marker + tail` 保留大型工具输出的开头和尾部诊断。
- Summary 记录来源页面、事件、成本、指纹和父 Summary。
- append-only 生命周期与 replay 验证支持 rolling compaction 和 crash-safe recovery。

## Phase 3

- 请求级 Token 计量覆盖 system prompt、消息、Tool Call、Tool Result、Tool Schema 与协议开销。
- Provider adapter 负责错误分类，Context VM 不解析 Provider-specific 字符串。
- Provider overflow 后只重建严格更小的请求并自动重试一次。
- 重试发生在 Assistant/Tool 事件写入之前，不会重复 Durable Tool side effect。
- 真实 Provider benchmark 为显式 opt-in，默认测试与 benchmark 均不访问网络。

## Benchmark

2026-08-25 使用同一个真实 OpenAI-compatible Provider 模型 `azure/gpt-5.4-2026-03-05` 运行三个上下文质量案例：

| Mode | Final Input Tokens | First Compaction Turn Total | Cases Passed |
|---|---:|---:|---:|
| Full History | 13,668 | 13,668 | 3/3 |
| Phase 1 | 5,605 | 5,605 | 2/3 |
| Phase 2/3 | 2,978 | 6,292 | 3/3 |

Phase 2/3 的最终请求输入比 Full History 少约 78.2%。第一次压缩需要额外 Summary 调用，因此总输入高于最终请求输入。Phase 1 在大型工具日志尾部错误案例中未保留 `FATAL: permission denied`；Phase 2/3 通过确定性裁剪与压缩保留该证据。三个案例均未触发真实 Provider overflow。详细逐案例数据、estimated/actual 差异和适用范围见 [`../../benchmarks/RESULTS.md`](../../benchmarks/RESULTS.md)。这些结果是 3/3 benchmark cases passed，不是通用 Coding Agent 成功率。

## Limitations

V0.4 仍不包含：

- 内置的精确 Provider tokenizer；
- Artifact / Resource Handle；
- long-term memory 或 RAG；
- Subagent 或 Scheduler；
- SQLite persistence；
- production telemetry。
