## 2. Architecture Decision

V0.8 is internally consistent with the OS-inspired Kernel boundary.

```text
LLM = untrusted proposer
Kernel = authority for mechanism invariants
Host = policy owner
```

V0.8 extends the V0.7 single-agent runtime with multi-agent runtime mechanisms
without collapsing Agent, Process, and Session.

```text
Agent   = capability principal and semantic actor
Process = schedulable runtime identity
Session = durable single-writer semantic journal
```

Release decision:

```text
ARCHITECTURE_AUDIT_PASS
```

## 3. Frozen Runtime Model

| Object | Frozen meaning |
| --- | --- |
| Agent | Capability principal and semantic actor. |
| Agent Tree | Semantic/authority lineage. |
| Process | Runtime identity scheduled by the Kernel. |
| Process Tree | Supervision, cancellation, and fault lineage. |
| Session | Durable single-writer journal and replay truth. |
| Context VM | Model-visible projection over Session truth. |
| Capability | Structured Agent-owned authority grant. |
| IPC | Kernel-owned data communication mechanism. |
| ResourceHandle | Reference to resource identity, not permission. |
| ResourceShare | Owner consent for exact cross-Agent Resource access. |
| UsageCollector | Runtime observation, not durable accounting truth. |
| Durable Tool WAL | Durable side-effect lifecycle and recovery obligation record. |

Frozen invariants:

- Agent != Process.
- Agent Tree != Process Tree.
- Process creation does not create an Agent principal.
- Process lineage does not imply capability inheritance.
- Session remains single-writer.
- Context is not truth.
- IPC payload is not authority.
- ResourceStore is not authorization.
- Accounting is not a ledger.
- Recovery reconstructs fresh runtime mechanisms from durable facts and current
  Host configuration.

## 4. Durable vs Runtime-Only State

| Durable semantic state | Runtime-only state |
| --- | --- |
| Agent identity/tree facts. | Scheduler ready/running/waiting/blocked queues. |
| Session events. | Live fault queues. |
| Process identity/tree creation facts. | UsageCollector counters. |
| Capability delegation provenance. | Runtime context working set. |
| IPC persistence state. | Temporary runtime indexes. |
| Resource metadata/ownership. | Runtime object identity. |
| ResourceShare facts. | Live scheduler admission state. |
| Durable Tool WAL facts. | In-memory IPC queue structures derived from persistence. |

Durable facts can be replayed. Runtime-only state must be rebuilt or supplied
by current Host policy after restart. Do not document process queues, scheduler
state, UsageCollector totals, or live working sets as durable truth.

## 5. Authorization / Delegation Model

Agent remains the authorization principal. Capability decisions are Kernel
mechanism:

```text
AuthorizationRequest(agent_id, action, resource)
  -> CapabilityEvaluator
  -> AuthorizationDecision
```

Delegation is explicit, positive, narrowed, and provenance-carrying:

```text
child effective authority
<= delegated authority
<= current parent effective authority
```

Historical delegation fact is durable provenance. It is not the same thing as
current effective authority. On recovery, current parent authority bounds which
historical delegations are activated for future work.

V0.8 does not claim complete revocation semantics, RBAC, IAM, or namespace
security.

## 6. IPC Model

KernelIPC owns channel identity, participant validation, message identity,
per-channel sequence, durable delivery state, and backpressure.

Implemented state machine:

```text
PENDING -> DELIVERED -> ACKED
```

V0.8 claims at-least-once observable delivery until ack for the tested local
point-to-point channel. DELIVERED but unacked messages may redeliver after
restart. No global ordering is claimed.

IPC transfers data only. A grant-like JSON payload, `resource_refs` entry, or
sender-provided identity field does not create authority.

## 7. Resource Sharing Model

`ResourceStore` remains storage and metadata persistence. It does not authorize.

Cross-Agent Resource access requires both:

```text
current Capability authorization
AND
active ResourceShare
```

Capability says an Agent may perform an action over a scope. ResourceShare says
the Resource owner consented to exact Resource access. One does not imply the
other.

Handle possession, IPC transfer, Agent lineage, Process lineage, or delegated
capability alone does not grant cross-Agent access.

## 8. Budget / Fault / Cancellation Model

Budget hierarchy:

```text
Host
  -> Agent
      -> Process
```

Budget checks happen at cooperative scheduler safe points. Budget exhaustion is
a runtime BLOCKED condition, not semantic task failure.

Child process fault does not automatically become parent process fault. Fault
notifications are runtime observations for Host policy.

Cancellation is cooperative. It is not rollback, not revocation, and not
deletion of durable facts. Durable WAL obligations and IPC persistence survive
process cancellation.

## 9. Recovery Model

Recovered runtime is:

```text
Validated Durable Semantic Facts
+ Current Host Configuration
+ Fresh Runtime Mechanisms
```

Recovered or reconstructed:

- Agent semantic identity/tree.
- Process semantic identity/tree.
- Session durable facts.
- Delegation provenance.
- Resource metadata and ResourceShare facts.
- IPC persistence state.
- Durable Tool WAL obligations.

Fresh after restart:

- Scheduler runtime queues.
- UsageCollector counters.
- Live Context working set.
- Runtime-only indexes.
- Object identity.

Integrated recovery is read-only. It reports recovery obligations and does not
silently retry, reconcile, restart, or admit processes to the scheduler.

## 10. Durable Side-Effect Model

Durable Tool side effects use operation identity and WAL semantics:

```text
Authorization
  -> WAL PREPARE
  -> dispatch authorization
  -> DISPATCH
  -> external effect
  -> COMMIT / ABORT / RECONCILE
```

Recovery classifications remain explicit:

- `SAFE_TO_RETRY`
- `IDEMPOTENT_RETRY_ALLOWED`
- `RECONCILE_REQUIRED`
- `COMPLETED`
- `MANUAL_REQUIRED`

Recovery is not retry. Recovery is not automatic reconciliation. Already
dispatched durable obligations may survive process failure, cancellation,
restart, and authority shrink for new work.

V0.8 does not claim universal exactly-once semantics.

## 12. Claim Boundary

Allowed claims:

- AgentKernel V0.8 implements and locally evaluates the tested runtime
  mechanisms.
- Deterministic offline RuntimeBench fixtures preserve the tested identity,
  authority, IPC, resource, budget, failure, and recovery invariants.
- Tested multi-agent recovery reconstructs durable semantic facts and fresh
  runtime mechanisms.
- Tested IPC redelivery does not implicitly transfer authority.
- Tested delegated authority remains bounded by current parent authority after
  restart.
- Tested durable side-effect fixtures preserve operation identity and surface
  reconciliation obligations.

Disallowed claims:

- production-ready runtime;
- production sandbox security;
- full OS/process isolation;
- distributed runtime correctness;
- distributed consensus;
- complete revocation semantics;
- namespace security;
- RBAC;
- IAM;
- multi-user security;
- universal exactly-once side effects;
- arbitrary external system atomicity;
- persistent memory correctness;
- LLM reasoning superiority;
- coding-agent superiority;
- superiority over LangGraph, AutoGen, Codex, DeepSeek Harness, or any other
  project;
- production SLA;
- general real-world reliability.

## 13. Known Limitations

- Synthetic fixtures.
- Offline local execution only.
- No external API calls.
- No production sandbox.
- No distributed runtime.
- No complete revocation engine.
- No namespace/RBAC/IAM system.
- No persistent memory.
- No preemptive scheduling.
- No production workload traces.
- No statistical repeated-run performance study.
- No claim about model intelligence or real-world task quality.
